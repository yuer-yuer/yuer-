### 2. ✅ 集成Tool调用到Agent节点

#### 更新的Agent
- ✅ nutrition.js - 营养顾问Agent
- ✅ fitness.js - 健身教练Agent

#### Tool调用流程
```
用户输入
  ↓
Agent接收 + RAG检索
  ↓
构建带工具描述的Prompt
  ↓
LLM生成回复（可能包含工具调用JSON）
  ↓
解析工具调用 → 执行工具
  ↓
将工具结果注入Prompt
  ↓
LLM生成最终回复（基于工具结果）
  ↓
返回给用户
```

#### 关键函数
1. `buildSystemPrompt()` - 构建带工具描述的Prompt
2. `extractToolCalls()` - 从回复中提取JSON格式的工具调用
3. `executeTools()` - 批量执行工具
4. `formatToolResults()` - 格式化工具结果供LLM使用

## 技术实现细节

### 工具调用协议

由于智谱GLM-4-Flash不支持原生Function Calling，采用**基于Prompt的工具调用方案**：

#### 1. Prompt注入工具描述
```
你可以使用以下工具来辅助回答：
- knowledge_retrieval: 从专业知识库中检索营养和运动相关知识
- calc_engine: 计算基础代谢率(BMR)、每日总消耗(TDEE)等
- food_query: 查询食物的营养成分

如果需要使用工具，请在回复中包含JSON格式的工具调用：
```json
{"tool": "工具名", "params": {...参数...}}
```
```

#### 2. LLM生成工具调用
LLM在回复中嵌入JSON：
```
用户询问鸡胸肉的热量，让我查询一下：

```json
{"tool": "food_query", "params": {"food_name": "鸡胸肉", "amount": 100}}
```
```

#### 3. 解析和执行
使用正则表达式提取JSON代码块：
```javascript
const jsonBlockRegex = /```json\s*(\{[\s\S]*?\})\s*```/g;
```

#### 4. 结果注入
将工具执行结果格式化后注入新的Prompt：
```
【工具执行结果】

工具1: food_query
参数: {"food_name":"鸡胸肉","amount":100}
结果: {
  "success": true,
  "data": {
    "calories": 133,
    "protein": 24.6,
    ...
  }
}

请根据以上工具执行结果，给用户一个详细、专业的回复。
```

#### 5. 最终回复
LLM基于工具结果生成回答：
```
根据查询结果，每100g鸡胸肉含有：
- 热量：133千卡
- 蛋白质：24.6g
...
```
